### Technical & Architecture Decisions (encoded here; groups/tasks must not re-decide)

1. **No local Rust toolchain.** The environment has no Rust/Cargo installed and must not assume it (TODO task 1 constraint). Therefore:
   - All project files (`Cargo.toml`, `src/*.rs`) are **hand-authored**, never generated by `cargo init/new`.
   - Tests are written and co-located with the code, but `cargo test`/`cargo build` execution is **deferred** (Docker build is a later phase). Verification in this phase = plan adherence + code review, not compilation.
2. **Dependency:** `rand = "0.8"` in `Cargo.toml` (the only dependency; no engine/TUI crates). Edition `2021`, package name `snake`, initial version `0.1.0`.
3. **File layout & rule compliance:** project rules cap source files at 200 lines (rule: max-lines-per-file) and methods at 50 lines. A single `main.rs` will exceed this once game logic + tests exist. Decision: split into small modules under `src/`:
   - `src/main.rs` — entry point, minimal (no terminal logic yet; prints nothing interactive, no I/O beyond trivial placeholder comment-free behavior decided in plans).
   - `src/game.rs` — module root wiring.
   - `src/game/position.rs`, `src/game/direction.rs`, `src/game/snake.rs`, `src/game/food.rs`, `src/game/state.rs` — one concept per file.
   - Unit tests live inline in the same module files (`#[cfg(test)] mod tests`) or in dedicated `src/game/state_tests.rs`-style modules; the architector fixes exact files per group, respecting the 200-line cap.
   - This satisfies context.md's "split into modules only if justified later" — the 200-line rule is the justification.
4. **Board constants:** centralized in `src/game/state.rs` (`pub const WIDTH: i32 = 40; HEIGHT: i32 = 25;` type per architector plan). Playable coordinates: `0..WIDTH-1`, `0..HEIGHT-1`. No wrap-around.
5. **Direction rule:** `Direction::opposite()` / rejections live purely in domain code, decoupled from input handling (TODO task 6).
6. **Snake representation:** `VecDeque<Position>` or `Vec<Position>` per architector decision; first element = head, documented in code via API naming (self-documenting-code rule; minimal comments).
7. **Food placement:** random via `rand`; occupied-cell retry; explicit handling when no free cells remain (simple explicit result/None/path per plan, no infinite loop).
8. **Game states:** enum `WaitingToStart | Playing | GameOver` representation only; transitions implemented; terminal UI/messages deferred (TODO task 13).
9. **Growth mechanics:** explicit `should_remove_tail` / `grow` flag path per architector plan; single movement routine serves both scenarios (TODO task 8).
10. **Front-end:** this TODO contains **no front-end related tasks** — all Phase 1A tasks are domain/logic only. No 4.1a/4.5a sub-steps; 4.1b/4.5b only.
11. **Rules that apply during implementation:** single-section boolean conditions (extract predicates into named methods), private members by default, no magic numbers (named constants), self-documenting names, no commented-out code, real newlines, files ≤200 lines, methods ≤50 lines, ≤2 args (group state into structs when needed), max indent 2 levels.
12. **Step 3 (version update)**: no versioned manifest exists at that point (Cargo.toml appears in Group A) → implementer verifies absence and reports "no version file; skipped". No commit for step 3.
