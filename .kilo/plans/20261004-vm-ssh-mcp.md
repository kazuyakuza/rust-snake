## Technical & architecture decisions (binding for all tasks)

1. **Runtime**: Node.js ESM (`.mjs`), no TypeScript build step — plain modern JS.
2. **SSH**: `ssh2` npm package (programmatic client). Windows OpenSSH `ssh.exe` cannot do
   non-interactive password auth; `ssh2` connects with `{ host, port, username, password,
   readyTimeout }` and `exec()`s commands, capturing stdout/stderr/exit code.
3. **MCP**: `@modelcontextprotocol/sdk` — `McpServer` + `StdioServerTransport`; tools
   registered with zod input schemas (`command: string`, optional `timeoutMs: number`).
4. **VM state probe (2 layers)**:
   - Layer 1: `VBoxManage showvminfo "alpine-virt-3.21.2-x86_64" --machinereadable`
     via `execFile`; parse the `VMState=` line → `running` | `poweroff` | `unknown`.
     `VBoxManage` path resolution: env override `VM_VBOX_MANAGE_PATH`, else
     `C:\Program Files\Oracle\VirtualBox\VBoxManage.exe`, else PATH lookup.
   - Layer 2: SSH probe — connect + exec `echo ok` with short timeout → boolean.
   - Combined `vm_status` result: `{ vmState, sshReachable, message }` with three
     meaningful states: VM off / VM on but SSH unreachable / ready.
5. **Command policy**: prefix allowlist. A command is allowed iff its trimmed form starts
   with one configured prefix followed by whitespace or end-of-string. Default prefixes:
   `docker,sh,apk,ls,cat,ps,df,free,uname,pwd,whoami`. Configurable via env.
6. **Status-only**: when the VM is not running, tools return a clear error/result;
   no `VBoxManage startvm` anywhere.
7. **Timeouts**: default command timeout 30000 ms (env-overridable); SSH `readyTimeout`
   5000 ms; VBoxManage probe timeout 5000 ms.
8. **Code rules** (from `.kilo/rules/`, apply to `src/`): ≤200 lines/file, ≤50 lines per
   function body, ≤2 nesting levels (extract helpers), ≤2 parameters per function
   (bundle into config/options objects), self-documenting names, no comments,
   private-by-default (export only what the server needs).
9. **Installs**: in-project only (`npm install` inside `C:\repo\vm-ssh-mcp`);
   `node_modules/` gitignored.

## Task 1 spec highlights (for architector 4.1b)

- `vm-connection-config.mjs`: read env once; validate `VM_SSH_PASSWORD` presence
  (throw descriptive error at startup if missing); freeze the config object.
- `vm-state-probe.mjs`: `execFile` with `windowsHide: true`, 5000 ms timeout; parse
  `VMState=` case-insensitively; map exec failure → `unknown` (never crash the server).
- `ssh-command-runner.mjs`: one `ssh2` `Client` per command (no pooling); `exec` with
  `pty: false`; resolve `{ stdout, stderr, exitCode }`; map connect errors to typed
  messages (`ECONNREFUSED` → "VM not reachable on <host>:<port>").
- `vm-tools.mjs`: `vm_status` = layer-1 probe (skipped → `unknown` if no name) +
  layer-2 probe; compose message. `vm_run_command` = status gate ("VM not running —
  start it in VirtualBox first") → policy gate (list allowed prefixes on rejection) →
  run → return compact text result with exit code, stdout, stderr.
- `server.mjs`: register both tools with descriptions telling the agent to check
  `vm_status` first; log startup line to stderr only (stdout is the MCP channel).
- `scripts/smoke-test.mjs`: spawn `node src/server.mjs`, write LSP-style newline-delimited
  JSON-RPC (`initialize` → `notifications/initialized` → `tools/list` → `tools/call
  vm_status`), read responses with a line buffer, print, kill child, exit code reflects
  success. Must work with the VM off (status = not running) AND on.

## Security notes (document in README)

- Password stored in plaintext in the global opencode config — acceptable for a
  disposable local dev VM; SSH key auth is the future hardening path.
- Allowlist limits blast radius; the VM is disposable.
- Server logs go to stderr only; never echo the password into tool results.
