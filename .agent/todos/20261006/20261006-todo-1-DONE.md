# Rapid-Direction-Swap Reversal Bug — Circling Kills the Player

## Context

The user reports a gameplay bug: with the snake in its initial 3-block state (no food consumed), a continuous movement in circles can make the player lose.

Root cause (pre-analysis): the game loop drains ALL buffered arrow directions chronologically and applies each via `change_direction` within a SINGLE tick, then advances one step. The domain's reversal rejection (`GameState::change_direction`) only compares the candidate against the CURRENT direction of the tick, not against the direction actually moved in the PREVIOUS tick nor against direction changes applied within the same tick. So quick key swaps like `Right → Up → Left` drained in one tick end with direction = `Left` (the immediate-reversal check passes against `Up`), and the snake steps onto its own 2nd segment → GAME OVER even though the player never performed a two-tick reversal.

Example scenario (initial snake at row 40, head (41,40) heading Right; body (40,40), (39,40)):
- Single tick with input `[Up, Left]` (or any 2+ presses between ticks): apply Up then Left → current direction = Left; step to (40,40) = own neck → GameOver. The snake visually doubles back onto itself.
- Triple press `Up, Left, Down` in one tick: apply Up → Left → Down; step to (41,41) (down) which is inside body → GameOver.
